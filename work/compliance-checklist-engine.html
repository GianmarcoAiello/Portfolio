Case study /01 — in production

COMPLIANCE
CHECKLIST
ENGINE

LLM judgement with auditable evidence. Reads invoices, purchase orders and bank transfers, answers each compliance checklist question with the evidence behind it, and returns structured results to the review platform the client already runs.

RoleLed design & delivery
ContextConsulting firm, enterprise
Status~5 customers in production
StackAWS serverless + Bedrock
01Context

Consultants manually checked invoices, purchase orders and bank transfers against per-customer compliance checklists. The process was slow, non-repeatable, and its quality depended entirely on which reviewer picked up the document. Five people did this full time.

02Approach

One REST endpoint in, one queue out — the engine plugs into the client's existing review platform without changing their document workflow. Two small Lambda functions and four managed services: capacity scales with queue depth and is capped to protect model quotas.

  • Rules live in versioned prompts, per customer and per document type — domain experts change a rule without a code release.
  • Structured answer per checklist question, each carrying its evidence.
  • Secure by default: private encrypted storage, API-key access with usage quotas, least-privilege roles, every step logged.
FIG.01 — request path in accent. Fill encodes step type: gray = deterministic code, red tint = model step, plain = external system. Dashed = async / return path.
03Results
  • Same workload: 5 manual reviewers → 1, at ~20 seconds per document.
  • Onboarding a new customer = a new rule set; infrastructure unchanged.
  • 5 active customers, 5 document types supported.
Lesson
The hard part was not the LLM call — it was making the output auditable: every answer carries its evidence, and reviewers trust the checklist because they can verify any row in seconds.
